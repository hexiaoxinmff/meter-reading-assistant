# 工具操作说明（维护人与豆包使用）

在技能目录运行；下列路径仅为示例，要替换成当前电脑的实际路径。每个命令只读取明确指定资料、把产物写到单独工作目录；不可覆盖原始照片和台账。脚本为本地工具，不负责识别或确定表计对应关系。Windows 建议先设置 `PYTHONUTF8=1`；若 Python、openpyxl、Pillow 或豆包文件执行能力不可用，报告缺项并使用客户端可用方式，不虚报成功。上传文件若没有可访问的本机文件路径，不能假设脚本能直接访问。

运行 `python scripts/check_env.py` 可查看当前 Python 找到的模块；结果不等于豆包客户端、模型或全部依赖已验证。

## 首次运行自动配置

解压技能包并确保豆包能够运行 Python 3.10+ 后，在技能目录运行 `python scripts/setup_environment.py`。脚本在当前用户的 `.meter-image-to-table/runtime-v06` 内建立虚拟环境，通过 pip 安装固定版本的 openpyxl、Pillow、PaddlePaddle 和 PaddleOCR；模型随包提供，先校验 SHA-256 再安全解压。依赖安装需要网络，可消耗较多时间和磁盘。JSON 中 `python` 为后续脚本的解释器路径，`core_ready` 和 `ocr_ready` 分别表示基础工具和 OCR 的依赖检查结果，不能由进程退出码单独认定 OCR 可用。两条模型路径在同一 JSON 中。默认每次检查但已安装时不重复安装；如只需要基础工具可加 `--core-only`。通过导入不等于每台电脑都已跑通 OCR，执行时仍要检查结果。若 OCR 失败但基础工具可用，使用视觉识别继续；Python 缺失、网络、权限或兼容性限制须报告。技能不会自行安装 Python 或更改系统全局环境。

## 清点与续跑

```
python scripts/batch.py init --manifest 工作目录/照片清单.json 照片文件夹 照片文件.jpg
python scripts/batch.py summary --manifest 工作目录/照片清单.json
```

init 递归清点指定目录内常见图片；每次输入算一项，即使同一文件在不同输入中重复。清单保存绝对路径和 SHA-256，完全相同内容仅标记疑似重复，须结合实际记录判断。文件名后缀可识别不等于格式可解码；HEIC 等文件取决于实际解码能力。仅能使用本机文件；新照片应另起批次。不要重复 init 覆盖旧清单。进程中断后读取原清单，summary 会标记缺失或改变的照片；修改后的照片不得沿用旧识别结果。

每次确认一张，先把确认后的 JSON 保存成 UTF-8 的 `工作目录/一张记录.json`，再执行：

```
python scripts/batch.py set --manifest 工作目录/照片清单.json --id P00001 --data 工作目录/一张记录.json
```

多张照片可一次写入：`python scripts/batch.py set-many --manifest 工作目录/照片清单.json --data 工作目录/多张记录.json`。文件是 JSON 数组，每个对象含 `id` 和下列字段。全部记录验证通过后才保存；单张有错误则整批不写入，修正后重试。

示例（仅示意，必须用实际识别和匹配结果）：

```json
{"status":"待填写","kind":"水","location":"示例楼层总水表","reading":123,"period":"2026-01","workbook":"D:/示例/手抄水表.xlsx","sheet":"Sheet2","cell":"B2","notes":"已检查水表类型和日期列"}
```

除“待填写”中间状态，最终状态为“已填写”“原表已有相同值”“重复照片”“待确认”“无法读取”或“未处理”。未知、冲突或无法读的字段不猜，填写 reason。待填写仅指识别和匹配明确，并未证明写入成功；写入和比对通过才标已填写。相同内容的照片须先确定重复，不可将同表不同时刻的照片自动判为重复。因进程中断无法确定是否写入时，先检查已经生成的文件、计划和状态，避免重写。

## 辅助查看

```
python scripts/image_view.py 原图.jpg 工作目录/辅助图.png --rotate 90 --crop 0 0 500 500 --scale 2
```

旋转按顺时针，裁剪坐标基于旋转后的像素尺寸；可单独使用其中选项。输出为新 PNG/JPEG。此工具只旋转、裁剪、插值，不改变原图，不可把放大后的模糊数字当成清晰事实。必要时重拍。

## 填表与检查

对每份台账分别运行；照片已核实且目标格空白时，清单的 status 才设为“待填写”。以下计划只来自人工/视觉已核实的清单，包含 before=null、after 数字及原台账哈希，重复目标单元格将报错；台账变化后必须重新核对并生成计划。

```
python scripts/batch.py plan --manifest 工作目录/照片清单.json --workbook 原表.xlsx --output 工作目录/填写计划.json
python scripts/fill_xlsx.py 原表.xlsx 工作目录/填表结果.xlsx --plan 工作目录/填写计划.json
python scripts/compare_xlsx.py 原表.xlsx 工作目录/填表结果.xlsx --expected 工作目录/填写计划.json
```

先对照计划中的每张照片、表计、周期、数值和目标单元格。fill 只支持 `.xlsx`、数值、空白格、新输出文件；拒绝公式、非空格、合并格、受保护表、签名工作簿与不支持的 XML。它通过定点修改工作表 OOXML 写入，不执行 Excel 重算，不能由此推断所有工作簿均兼容或所有公式缓存已更新。失败时保留原表，逐项处理。compare 为只读核验：检查指定的值、公式、样式和部分工作表结构，不覆盖图表、宏、外链、页面视觉或全部元数据。需按实际情况另行检查、说明范围。仅在填入和检查完成后，将相应照片逐条改为“已填写”。

## 人工复核页

```
python scripts/review.py --manifest 工作目录/照片清单.json --html 工作目录/照片复核.html --csv 工作目录/照片明细.csv
```

HTML 内嵌缩略图，CSV 为文字明细，均可能含内部信息。原图变化或丢失时不展示对应缩略图。HTML 为静态报告，不能点击改状态；需要用 set 更新清单后另生成新报告。缩略图并非读数确认依据，应回看原图。

## 可选 OCR

`scripts/ocr_optional.py` 适配已安装的 PaddleOCR 3.x / PaddlePaddle 和由维护人事先准备的本地文字检测与识别模型：

```
python scripts/ocr_optional.py 原图.jpg --det-model-dir 本地检测模型目录 --rec-model-dir 本地识别模型目录 --output 工作目录/文字辅助.json
```

禁用方向和图像矫正附加模型，并显式指定模型目录；OCR 脚本本身不安装库或下载模型；首次环境脚本安装依赖并解压随包模型。库、模型、网络行为及许可证应由维护人按实际环境核实。OCR 仅是候选文字，不做水表指针解释或自动写表；无法运行时仍可用视觉识别。不同版本与模型兼容性必须先实测，不能声称必然离线或准确。官方文档：https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/OCR.html


本机样本测试中水印文字可辅助提取，但电表数字曾被 OCR 误识别，因此绝不能把 OCR 数字直接写入。OCR 与豆包自身视觉能力是不同工具。

模型来源：PaddleOCR 官方 PP-OCRv5 mobile 检测与识别推理模型，参考 https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/OCR.html 及 https://github.com/PaddlePaddle/PaddleOCR/blob/main/LICENSE 。
