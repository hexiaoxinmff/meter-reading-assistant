# 异常复核与续跑

按用户指定照片和对应水、电台账工作，不要求用户掌握编号或命令。说“把这个文件夹里的水电表照片填进这两张台账”即可开始；缺少水表或电表台账时处理现有的另一类，缺少的列入待处理。

## 异常清单

每张照片保留编号和原图路径（若上传附件无可访问路径，保留客户端可追踪标识），类别、拍摄日期、照片位置、可辨读数、目标工作簿/工作表/候选单元格、具体疑点、候选依据、需要同事确认的内容及状态。区分读数看不清、总表分表不明、周期不明、无对应记录、多个候选、旧值不同、表计更换或倍率不明。优先列出待确认、无法读取及未处理项；对反光、遮挡和模糊写出实际发现，必要时建议补拍。不要将自动图片质量评估说成已经实现。HTML/CSV 是现有脚本的静态明细，不能在其中直接确认或修改状态；需要时在聊天中补充它未包含的候选依据。

## 确认后的续跑

1. 让同事按照片编号明确确认需要纠正的字段、目标位置或补充新照片；只应用明确确认内容。读取已有清单及上一轮计划和核对报告，确认已完成、已有相同值与未完成项目，不重复写入。
2. 确认原图哈希、对应台账版本、位置、日期列、目标格与原值；文件变化、目标非空或仍有冲突时停止该项。新增照片另建清单，保留与原编号的对应关系。
3. 用 batch.py set 或 set-many 修改已确认项目；生成新一轮计划。以最近一次已核验的输出文件作为本轮输入（首次无成功输出则使用原始台账），先备份当前结果，再调用 update_result.py 更新相同路径的结果文件，并比较本轮备份和输出。保留之前备份，若目标格已有值则按既有规则处理。
4. 写入并检查成功后更新状态、重新生成新的 HTML 和 CSV；报告本轮变化、累计结果与仍需处理的项目，以照片输入为单位核对数量。输出原始输入、固定结果、每轮备份和复核记录的路径。中断或不确定是否已写入时先检查已有文件和日志。

## 表计映射（人工确认后保存）

映射是经办人确认过的参考记录，存入经办人指定的工作资料目录，例如 `表计对应关系.json`，不加入技能包和 Excel 原表。结构建议：`{"version":1,"mappings":[{"kind":"水","photo_name":"示例位置","meter_id":"示例编号或未知","workbook_identity":"示例台账标识","ledger_name":"示例台账名称","ledger_meter_id":"台账表号","evidence":"核对依据","confirmed_by":"确认人","confirmed_date":"YYYY-MM-DD","status":"有效"}]}`。示例不是实际数据；无可靠表号时明确未知，不得虚构。记录确认依据与日期，可按用户要求保存可辨识人员信息；用户未同意保存则只在当次会话使用。

每次使用映射时，在当前台账根据位置、表种、表号和名称重新检索，映射不存固定行列作为永久位置，周期列仍按当前台账确定。用户确认对应关系后才新增或修改映射；同名多表、设备换表、账册版本变化、表号不符或证据不足时列候选并暂停该项，旧记录保留并标记待复核。不要自动覆盖旧记录。映射文件可能含业务信息，妥善存储；当前技能没有自动维护或匹配映射的专用程序，由豆包按本流程读取和维护。
